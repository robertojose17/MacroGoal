# Durable goal journal: native source integrated, not device verified

Onboarding and accepted-goal editors now share one session per owner/project. Native storage uses Expo SecureStore with `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. The source declares the official `expo-secure-store` plugin with `configureAndroidBackup: true`. No native artifact has been built or inspected; declaring the plugin is not proof of its effective configuration on a device. Web is rejected, not given an unencrypted fallback.

The journal stores chunks of at most 1,200 UTF-8 bytes, a SHA-256 digest, and a manifest committed after chunks. Readback precedes any RPC. A resolved marker precedes cleanup and UI success. Payload, request UUID, nullable/microsecond profile and goal CAS remain immutable. Hydration is read-only. Replay requires an explicit user action; requests rejected definitively require explicit review and asynchronous cleanup.

One shared controller pair distinguishes owning a request from the other operation's mirror lock. Onboarding may only replay `initial_onboarding`; Settings may only replay `manual_goal` or restart. Recovery callers are serialized and actor/focus guards are checked. After resolution or review, both controllers rehydrate. No goal calculations are used to reconstruct an RPC.

Android SecureStore can return null on key loss or invalidation. A separate non-sensitive presence witness is committed and verified before the encrypted head. It stores only the literal `present`, never health data, request payloads, CAS or credentials. A missing encrypted head with a witness blocks new writes and requests reconciliation instead of claiming an empty journal. Interrupted cleanup can also require reconciliation. If both storage domains disappear, for example on uninstall, this witness cannot prove that an earlier request existed; server/device reconciliation remains a release test and recovery limitation. Do not claim exactly-once recovery across reinstall or total storage loss.

Cold onboarding opens the existing retry/review controls directly, not a blank body-data form. The unchanged final onboarding/paywall receives presentation values from the original accepted payload after replay, rather than defaulting missing weights to zero. The inherited initial timeline convention remains an estimate, not measured TDEE or a new adaptive recommendation. No proposal, cron, recommendation or observation flag is enabled.

Tests run the actual TypeScript session, controllers, journal, adapter and hooks with simulated storage/auth/database. They cover cold replay, scope isolation, actor/focus changes, three concurrent recoveries, definitive rejection, uncertain outcomes and lost head/key detection. They are not native process-kill, backup/restore, reinstall, hardware-key, or authenticated account E2E tests.
